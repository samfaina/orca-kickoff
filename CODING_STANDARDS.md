# Coding standards

Read during review. Each rule is a judgement call: what `orca plugin validate`, `test`, `check` and `tsc` already catch isn't repeated here.

- **Parallel helpers change together.** When a diff changes one helper of a family that repeats a pattern, such as `withIntervals` and `withTimeouts` in `src/panel.test.tsx`, it makes the same change in the others, or the PR says why not.
- **Comments follow the code.** A comment that describes behaviour the diff changes is updated in the same diff.
- **A call nobody awaits handles its own failure.** A call started with `void`, or otherwise not awaited, as in an `onPress`, `onSubmit`, `setTimeout` or `setInterval` callback, never drops a rejection. There are two safe forms: the function it calls catches everything it awaits and turns a failure into a value or a shown error, as `askTasks` and `refreshWorktrees` in `src/panel.tsx` do, or the call itself ends with a `catch`. A function that lets a rejection through, such as `checkStarts`, is fine while every caller awaits it inside a `try` that catches, as `poll` does; a new caller that doesn't is the bug. Code that runs after the await counts too: a `then` callback that can throw, such as one that posts to the panel, needs the same care. `tsc` doesn't report a dropped promise, and in the worker an unhandled rejection ends the process (`docs/reference.md`, Worker process).
